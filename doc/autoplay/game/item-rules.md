# 道具／寵物處置規則表（唯一來源）

> **使用者每講一條新規則 → 只改這份表，不寫一次性腳本、不改程式常數。**
> 程式 `x7k2qm/autoplay/item_rules.py` 直接解析本檔的兩張表（「處置規則」「保護名單」），
> 固定指令 `python -X utf8 -m x7k2qm.autoplay.jobs clean`（[`../flows/jobs.md`](../flows/jobs.md)）照表執行。
> 表格格式改壞、ID 和名稱對不上設定表、刪除清單碰到保護名單，`tests/autoplay/test_jobs_item_rules.py` 會失敗。

## 規則怎麼讀

- **一律用 ID 比對**（道具＝`Item.json` 的 ID，寵物＝`Monster.json` 的 petId），名稱只是給人看的，
  但測試會核對「名稱＝設定表名稱」，抓打錯的 ID（手冊寫「老爺爺護身符」實際叫「老爺爺的護身符」，用名稱比對會整個漏掉）。
- 同一個 ID 可以有好幾列（不同條件）；**由上往下第一列條件成立的算數**，沒有一列成立就不動。
- **穿在身上的裝備一律不動**（`itemStorge ≠ 0`）；**戰寵、騎寵一律不動**（狀態 2／3，或外掛鎖定的唯一編號）。
- 條件寫法（多個用「、」連接，全部成立才算）：
  - `—`：無條件。
  - `trans=0`、`trans>=1`：角色轉數（`RoleAttr.trans`）。轉數不知道就當不成立（不動）。
  - `done=2032`：該角色 `finishTasks` 含這個任務群組。不知道也當不成立。
  - `depot<1`、`depot>=1`：**這個角色個人倉庫裡這個 ID 的件數**。用來寫「個倉只留 N 件，多的丟掉」：
    上面一列 `store_private｜depot<1`（個倉還沒有就存進去）、下面一列 `delete｜depot>=1`（已經有了就丟）。
    同一批背包裡有好幾件時會**邊存邊算**（存掉第一件後，第二件看到的就是 1 → 落到刪除那列）。
    沒查倉庫或查失敗時件數是「不知道」→ **兩列都不成立、什麼都不動**（寧可不刪）。
  - `leftover`：永遠成立，只是標記「任務用剩的、使用者核准丟」。**任務條件道具**（`Task.json` 條件用到的）
    要刪，規則一定要寫 `leftover` 或 `done=群組`，不然算清單時就停；保護名單裡的不論寫什麼都不准刪。

| 處置 | 意思 | 協定 | 可逆 |
| :-- | :--- | :--- | :-: |
| `delete` | 刪除 | `Item_batchDelItem{itemIndexList}`，一次 ≤5 格，逐格核對 itemId，刪完確認那幾格消失、其他格沒變 | ✗ |

| `keep` | 留在背包，不動 | — | — |

| `release` | 寵物放生（進回收站 48 小時）；另要加 `--confirm-release` 才做 | `Pet_DropPet{petIndex}`，等該格 petId ≤ 0 | ✗ |

## 新增一條規則的步驟

1. 查 ID：`data/configs/Item.json`（道具 `nameTn`）或 `Monster.json`（寵物）。
2. 在「處置規則」加一列，**核准**寫使用者說的日期、**出處**寫原話或文件。
3. `python -m pytest -q tests/autoplay/test_jobs_item_rules.py`（名稱對不上、碰到保護名單都會失敗）。
4. 先跑 `clean` 不加 `--apply` 看清單，確認後才 `--apply`。
